# FgmSSH 候选功能规划清单（Feature Roadmap）

> 定位：单人 IT 使用 + Windows portable 绿色单文件交付（~80MB）
> 原则：不脱离场景堆功能；能复用现有 SSH/SFTP 通道的优先；工作量按"增量开发"诚实评估。
> 工作量参考：S = 1~2 人日，M = 3~5 人日，L > 1 周
> 优先级：P0 高价值低成本 / P1 中价值常规投入 / P2 锦上添花

---

## 1. 现有功能盘点（已确认）

| # | 功能 | 现状一句话 |
|---|------|-----------|
| 1 | 多会话标签页终端 | xterm 终端 + 多标签，支持终端 `cd`→SFTP 面板联动、面板右键 `cd`→终端同步（双向 cd-sync）。 |
| 2 | 连接列表抽屉 | 保存连接配置（密码/私钥/agent 三种认证）、搜索、删除；配置明文落盘 `%APPDATA%/FgmSSH/connections.json`。 |
| 3 | SFTP 文件面板 | 浏览/上传/下载/文件夹 ZIP 打包下载/新建/重命名/删除 + 右键菜单 + 传输进度条。 |
| 4 | 图片预览器 | SFTP 内图片预览，支持左右切换/缩放/旋转/另存为。 |
| 5 | 内置文档查看器 | PDF（pdfjs-dist）/Word（mammoth）/TXT 打开；TXT 可编辑并保存回远端，PDF/Word 只读。 |
| 6 | 操作日志系统 | 主进程 JSONL 按天落盘、白名单字段 + 脱敏、条件查询分页、面板查看（audit-log）。 |
| 7 | 外观与基础体验 | 深色主题（CSS 变量已集中管理），无浅色切换；单实例锁；无托盘/自启/更新检查。 |
| 8 | 交付形态 | Windows portable 单文件绿色 exe；窗口关闭即清理所有会话（会话不保活）。 |

## 2. 候选功能清单（24 项）

### 2.1 SFTP 相关

| 功能 | 解决什么问题 / 价值点 | 实现要点（落点） | 工作量 | 优先级 |
|------|----------------------|------------------|--------|--------|
| SFTP 拖拽上传 | 上传是最高频操作，拖拽比文件选择器快 | 渲染层捕获 dragover/drop，`webUtils.getPathForFile` 取路径后复用现有 `sftpUpload` IPC（主进程通道已就绪） | S | **P0** |
| 传输队列 / 批量操作 | 多文件上传下载排队、失败重试、汇总进度 | 主进程加队列管理器；渲染层扩展现有单文件进度条为队列视图 | M | P1 |
| 断点续传 | 大文件网络中断后从偏移续传，不重头再来 | 主进程 `sftp.createReadStream({start})` + 本地 `.part` 文件管理与合并（ssh2 fastGet 不支持续传，需手写） | M | P1 |
| 文件搜索 / 过滤 | 目录文件多时快速定位 | 客户端即时过滤：渲染层对已加载条目过滤（S）；服务端递归搜索：主进程 `conn.exec('find …')` + 结果回填（M，可后做） | S/M | P1 / P2 |
| 双栏目录对比 | 两个目录（远程-远程/远程-本地）并排比对差异 | 纯前端双面板布局 + 复用 `sftpList`；对比差异走主进程递归列举 | M | P2 |
| 文本在线编辑增强 | 现有 TXT 打开+保存已具备，补语法高亮与大文件分段加载 | 纯前端（编辑视图升级）+ 复用 `doc:save`；1MB+ 文本分段拉取 | M | P2 |

## 3. 推荐优先做的 Top 5（P0 全量入选）

### ① 连接凭据加密存储（M）
- **为什么**：安全工具存明文凭据是本产品最大的信任缺口；Windows DPAPI 是原生零依赖方案，改动面小。
- **预期收益**：消除明文密码/私钥路径外泄风险；旧配置自动迁移，用户无感。
- **最小实现范围**：主进程 `safeStorage.encryptString` 加密 password/passphrase → 读时解密 → 首启自动迁移旧明文。渲染层无改动。

### ② SSH 隧道 / 端口转发管理面板（S）
- **为什么**：后端与 IPC 通道**已写好**（`createTunnel`/`ssh:tunnel`），只差 UI——"代码已就绪、只缺入口"的最高性价比功能。
- **预期收益**：解锁跳板机、内网穿透、数据库本地直连等高频运维场景。
- **最小实现范围**：渲染层隧道配置面板 + 主进程把隧道配置随连接持久化并自动建立；复用现有 `createTunnel`，不新增通道代码。

### ③ SFTP 拖拽上传（S）
- **为什么**：上传是最高频操作之一；现有 `sftpUpload` 通道可直接复用，纯增量。
- **预期收益**：上传交互效率显著提升，符合"文件管理器"心智。
- **最小实现范围**：渲染层 drop 事件 → `webUtils.getPathForFile` 取路径 → 调现有 `window.nimbus.sftpUpload`；复用进度条。

### ④ 常用命令收藏夹（S）
- **为什么**：纯前端 localStorage 即可落地，成本近乎为零；重复命令场景每天发生。
- **预期收益**：日志/重启/监控等命令一键发送，减少输入与误操作。
- **最小实现范围**：收藏夹下拉 + localStorage 持久化 + 点击后 `ssh:write` 写入当前终端；不做命令模板变量等扩展。

### ⑤ 配置加密导出 / 导入（S）
- **为什么**：绿色单文件用户换机/备份是刚需；与①共用加密能力，增量成本小。
- **预期收益**：一键备份/迁移全部连接，且导出文件加密不外泄。
- **最小实现范围**：主进程 AES-GCM 加密导出 JSON + 导入校验；渲染层两个按钮 + 密码输入框；复用①的加密工具函数。

## 4. 不建议做 / 慎做

| 功能 | 结论 | 原因 |
|------|------|------|
| 定时任务（cron 式） | **不建议** | 需常驻调度器 + 状态持久化，工作量大（L）；IT 用户本可在服务器上用 crontab 完成，客户端侧价值低；与"绿色单文件、用完即走"定位冲突。 |
| 团队共享配置 / 云端同步 | **不建议** | 需要账号体系 + 服务端基础设施，与单人定位严重不符；换机/协作用「配置加密导出/导入」即可覆盖 90% 需求。 |
| 完整终端会话录制回放 | **慎做** | 输出全量落盘存储膨胀、回放引擎成本高（M→L）；现有 audit-log 已覆盖关键操作追溯。若确需，降级为"终端输出全文搜索"（P2）再评估。 |

**边界说明**：RDP / VNC / 云厂商管理面等超出 SSH 客户端定位的能力，一律不纳入规划。

---

## 5. 决策参考（一句话）

- 优先做「安全补短板（①⑤）+ 已就绪通道补入口（②）+ 高频操作提效（③④）」；
- P1 中建议按「传输可靠性（断点续传/队列）→ 多机提效（批量执行/分屏）→ 保活与备份（托盘/审计导出）」顺序推进；
- P2 全部为增量体验项，随时可砍，不影响核心链路。
